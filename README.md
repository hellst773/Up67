# RolesMod (ДрузьяMod) — up67

Minecraft 1.20.1, Forge, Java 17.

## Что делает мод

Блок **Апгрейдер**. Крафтится из золота, алмазов и наковальни (как в рецепте ниже).
Ставишь блок, жмёшь ПКМ — открывается GUI.

В GUI два слота:
1. Предмет, который хочешь улучшить (деревянный меч, кирка, броня и т.д.).
2. Материал-оплата (например, железо для апгрейда с камня на железо).

Жмёшь кнопку **«ПРОКАЧАТЬ»** — апгрейдер с заданным шансом либо выдаёт
улучшенную версию предмета, либо сжигает исходник (с шуточным сообщением в чат).

Цепочки апгрейда: дерево → камень → железо → алмаз → незерит для мечей, кирок,
топоров, лопат, мотыг и брони (кожа/железо/алмаз/незерит). Плюс несколько
мемных "почти невозможных" апгрейдов (палка → слиток незерита с шансом 0.01%,
и т.п.) — просто ради прикола.

Шутки/приколы реализуются через `up67.rolesmod.upgrade.JokeMessages` — там
пул фраз на успех и на провал, можно редактировать и добавлять свои.

## Рецепт крафта

```
G D G
D A D
G D G
```
G = золотой слиток, D = алмаз, A = наковальня.

## Сборка через GitHub (без своего компьютера)

В репозитории уже лежит `.github/workflows/build.yml` — GitHub Actions сам
соберёт мод при каждом пуше.

1. Создай новый репозиторий на GitHub (можно пустой, публичный или приватный).
2. Залей туда содержимое этой папки целиком (через веб-интерфейс "Add file →
   Upload files" — перетащи все файлы и папки, включая скрытую `.github`,
   либо через git: `git init && git add . && git commit -m "init" && git push`).
3. Открой вкладку **Actions** в репозитории — сборка запустится сама
   (workflow называется "Build mod").
4. Когда сборка зелёная (galочка), зайди в неё и внизу найди раздел
   **Artifacts** → скачай `RolesMod-jar` — это zip с готовым .jar мода внутри.
5. Если сборка красная (ошибка) — открой лог шага "Build mod jar" и пришли
   мне текст ошибки, поправлю код.

Важно: если через веб-интерфейс GitHub не загружает скрытую папку `.github`
(иногда drag-and-drop её игнорирует) — используй `git` с компьютера или
переименуй/загрузи файл `.github/workflows/build.yml` отдельно через
"Add file → Create new file" и вставь путь `.github/workflows/build.yml` +
содержимое.

## Сборка на своём компьютере (альтернатива)

1. Установи JDK 17.
2. Скачай `gradlew`/`gradlew.bat`/`gradle/wrapper/*` из официального Forge
   MDK для 1.20.1-47.3.0 (https://files.minecraftforge.net/) и положи поверх
   этого проекта — они отсутствуют в zip, так как среда без доступа к
   services.gradle.org их не генерирует.
3. `./gradlew build` (Linux/macOS) или `gradlew.bat build` (Windows).
4. Готовый .jar будет в `build/libs/`.

## Где что лежит

- `up67.rolesmod.RolesMod` — точка входа мода, регистрация реестров.
- `up67.rolesmod.block.UpgraderBlock` — сам блок, открывает GUI по ПКМ.
- `up67.rolesmod.menu.UpgraderMenu` — контейнер (логика слотов и кнопки).
- `up67.rolesmod.client.UpgraderScreen` — визуальная часть GUI.
- `up67.rolesmod.upgrade.UpgradeRegistry` — таблица "что во что апгрейдится".
- `up67.rolesmod.upgrade.JokeMessages` — шутки на успех/провал.

## Как добавить новый апгрейд

Открой `UpgradeRegistry.java` и в статическом блоке добавь строку:

```java
add(Items.ИСХОДНЫЙ_ПРЕДМЕТ, Items.ЦЕЛЕВОЙ_ПРЕДМЕТ, Items.МАТЕРИАЛ_ОПЛАТЫ, КОЛИЧЕСТВО, ШАНС_УСПЕХА_ОТ_0_ДО_1);
```

## Важное замечание по исходному файлу

Ты прислал `upgrader-fabric-1.3.0-1.21.11.jar` — это готовый мод **Upgrader**
от автора execheinz, но:
- он собран под **Fabric**, а не Forge;
- он сделан под **Minecraft 1.21.1**, а не 1.20.1;
- в jar нет исходников — только скомпилированные `.class`-файлы.

Поэтому "портировать" его напрямую было нельзя — код пришлось написать заново
под Forge 1.20.1, взяв из оригинала только общую идею (блок-станция с GUI,
апгрейд предметов по шансу) и тексты интерфейса. Полный функционал оригинала
(каталог всех предметов игры, "колесо фортуны", экран настроек, сетевая
синхронизация, кастомные цены) в этой версии не реализован — это заняло бы
на порядок больше кода. Если нужно что-то из этого добавить — скажи, сделаю
отдельным шагом.
